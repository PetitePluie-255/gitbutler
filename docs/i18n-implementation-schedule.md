# GitButler 零侵入 i18n 排期与优先级判定

> 基于 `docs/i18n-implementation-tasks.md` 的实施落地排期与验收口径。
> 时间基准：2026-03-04（本地时间），以“人天”为估算单位。

---

## 一、总体优先级判定

1. **P0 核心可用**（最高优先级）
2. **P1 动态轻量**
3. **P2 辅助流程**
4. **P3 TS/JS 白名单替换（可选）**

约束原则：
- **零侵入优先**：仅通过 preprocessor/Vite plugin 注入，不改业务源码
- **稳定优先**：宁可少翻也不引入脆弱替换
- **开发体验优先**：dev 可记录日志，build 不引入监听与副作用

---

## 二、阶段排期（人天）

### P0 核心可用（1-2 天）
目标：完成预处理器骨架、字典加载、静态文本/属性替换、日志机制与构建链挂载。

产出：
- `packages/i18n-preprocessor/*` 初版
- `locales/zh-CN.json` 空字典
- `missing-en.log` 机制（dev-only）
- 构建链可运行、可禁用

验收标准：
- 构建/运行零报错
- 静态文本替换与属性替换生效
- dev 模式能生成 `missing-en.log`，build 不生成

### P1 动态轻量（1 天）
目标：支持单变量插值场景，复杂表达式跳过。

验收标准：
- 常见插值可翻译
- 复杂表达式不崩溃、静默跳过

### P2 辅助流程（0.5-1 天）
目标：补全字典生成、diff、stale 检测与合并 SOP。

验收标准：
- 一条命令发现新增/过期翻译
- 字典维护流程可复用

### P3 TS/JS 白名单替换（可选）（1 天）
目标：最小范围内替换 TS/JS 文本，具备误伤防护。

验收标准：
- 不替换逻辑字符串/路径/比较条件
- 有 dry-run 与 diff 预览

---

## 三、里程碑与交付顺序

1. **M0（Day 1）**：完成 P0
2. **M1（Day 2）**：完成 P1
3. **M2（Day 2-3）**：完成 P2
4. **M3（可选）**：完成 P3

说明：
- 若只有 1 人实施，默认 P0-P2 在 2-3 天内完成
- P3 仅在实际需求明确时启动

---

## 四、风险与缓冲

- **动态插值复杂度**：P1 只做单变量，复杂表达式跳过
- **HMR 性能**：日志与监听只在 dev 开启，build 关闭
- **上游变更**：P2 的 diff + stale 检测作为常规维护手段

---

## 五、执行顺序（从现在开始）

1. P0-1 包骨架搭建
2. P0-2 字典加载与开关
3. P0-3 静态文本替换
4. P0-4 属性替换
5. P0-5 missing-en.log
6. P0-6 构建链挂载
